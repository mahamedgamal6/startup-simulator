# مصانع الزنوكي — نظام التكاليف الصناعية وبطاقة المنتج الرقمية

تطبيق ويب عربي (RTL) لإدارة تكاليف الإنتاج في مصانع الزنوكي للأواني المنزلية، يربط بطاقة المنتج الرقمية بالخامات والإكسسوارات والتعبئة ومراحل التشغيل والماكينات والإسطمبات ونتائج الجودة، ويحسب التكلفة والهامش لكل منتج.

- **الإصدار:** 1.5
- **النسخة المنشورة:** https://site-6e5bcc5b5f0d4cf3a367a3e8e14e756d.freebuff.page

## المزايا

| الشاشة | الوظيفة |
| --- | --- |
| لوحة القيادة | مؤشرات الأداء والربحية ومقارنة المنتجات وتصدير التقارير |
| بطاقة المنتج | بطاقة رقمية لكل منتج: الصور، الخامات، الإكسسوارات، التعبئة، مراحل التشغيل، التكلفة والهامش، وطباعة البطاقة التفصيلية |
| التحليل المالي | تفصيل عناصر التكلفة، الهوامش، ومحاكي أسعار الخام |
| الإنتاج والماكينات | خطوط الإنتاج والماكينات والإسطمبات وأزمنة التشغيل وقطع الغيار |
| الجودة والتشغيل | البطاقة الفنية وخطة الفحص ونتائج الفحوصات |
| مركز البيانات | إدارة الجداول والاستيراد والتصدير (Excel) والنسخ الاحتياطي |
| المستخدمون | إنشاء الحسابات وتعديلها وكلمات المرور |
| الأدوار والصلاحيات | مصفوفة صلاحيات تفصيلية لكل دور |
| سجل العمليات | تتبّع كل إجراء على المنصة |

من مزايا التطبيق أيضًا: معاينة مكبّرة للصور، رفع/حذف صور المنتجات والإكسسوارات، دعم كامل للعربية وRTL.

### طباعة بطاقة المنتج

زر «طباعة البطاقة» في شاشة بطاقة المنتج يفتح بطاقة طباعة شاملة قابلة للطباعة تتضمن:

- **هوية المنتج:** الاسم، الكود، الباركود النصي، العائلة، المقاس، السعة، السُمك، القطر، معامل الأمان، وعبارة تغليف المنتج.
- **صورة المنتج:** الصورة الفعلية المرتبطة بالمنتج (أو الشكل الافتراضي عند غيابها).
- **باركود قابل للمسح:** يُولَّد تلقائيًا بصيغة EAN-13 عند صحة رقم التحقق (Checksum)، وبصيغة Code128 كبديل لأي كود آخر.
- **تفاصيل المنتج من البداية للنهاية:** المواصفات والمقاسات، المواد الخام المباشرة (الكود، السبيكة، القطر والسُمك، وزن القرص، الهالك، السعر والتكلفة)، الإكسسوارات ومكونات التجميع (المادة، العدد/قطعة، المنشأ، والتكلفة)، التعبئة والتغليف (الأبعاد، الوزن الفارغ، القطع الداخلية، والتكلفة).
- **التكلفة والشحن والتصدير:** تفكيك التكلفة الصناعية، وبيانات الحاويات 20/40 قدم (السعة، الحمولة، عدد الكراتين والقطع، وزن الشحنة، الحجم المستخدم، القيمة التقديرية، والجاهزية).
- **التصنيع والجودة:** مراحل التصنيع بالتفصيل (الوصف الفني، الماكينة، الإسطمبة، العمال، الزمن والتراكمي) من رحلة التشغيل، ونقاط الفحص والاختبار.
- **وضعان للطباعة حسب الصلاحية:** «البطاقة الرسمية» تعرض التكاليف والقيم المالية، و«البطاقة الفنية» (لمشرف الجودة) تخفي الأعمدة والقيم المالية مع الإبقاء على كل التفاصيل الفنية والإنتاجية.

## التشغيل المحلي

```bash
git clone https://github.com/mahamedgamal6/startup-simulator.git
cd startup-simulator
npm ci
```

يستخدم `npm ci` ملف `package-lock.json` لتثبيت نسخ الحزم المطابقة تمامًا (يمكن استخدام `npm install` بدلًا منه إذا عدّلت الحزم).

أنشئ ملف `.env.local` في جذر المشروع:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

ثم شغّل:

```bash
npm run dev
```

وافتح: http://localhost:5173

> لا تضع مفتاح `service_role` في ملفات الواجهة أو في `.env.local`؛ استخدم المفتاح العام `anon` فقط.

## إعداد قاعدة البيانات

يستخدم التطبيق مخطط `elzonki` داخل Supabase، وتُطبَّق التغييرات عبر ملفات SQL مرتبة في `supabase/migrations`:

1. `20261109_factory_sync_tables.sql` — جداول المنتجات والخامات والإكسسوارات والتعبئة وعناصر التكلفة والإعدادات.
2. `20261109_factory_sync_machines_molds_inspections.sql` — الماكينات والإسطمبات ونتائج الفحص والمزامنة.
3. `20261109_factory_sync_rpcs.sql` — دوال القراءة والكتابة والتحقق من الجلسات والصلاحيات.
4. `20261109_factory_media_parts_stages.sql` — صور الكيانات وقطع الغيار ومراحل التشغيل.

طبّقها بالترتيب من **SQL Editor** في لوحة Supabase، أو باستخدام Supabase CLI:

```bash
supabase link --project-ref <project-ref>
supabase db push
```

يتوفر `supabase/seed/factory-data.json` كبيانات تجريبية مرجعية للمنتجات والخامات والإكسسوارات، ويمكن استيراد الجداول من شاشة **مركز البيانات** بصيغ CSV أو Excel.

**ملاحظات أمنية:**

- تفعيل RLS على جداول البيانات، والقراءة والكتابة تمر عبر دوال RPC تتحقق من صلاحيات الدور.
- الصور تُخزَّن كـ Data URLs في جدول `elzonki.images` عبر دوال مخصصة.
- مفتاح `anon` عام بطبيعته ويُضمَّن في الواجهة، لذلك الحماية الفعلية تعتمد على صلاحيات RPC وRLS.

## الرش والتكلفة التلقائية
- **عناصر التكلفة** تُحسب تلقائيًا لكل منتج من البيانات المرتبطة (خام، إكسسوارات، تعبئة، رش/طلاء، ومعدلات مصنعية/مصاريف تقديرية) ولا تظهر في مركز البيانات ولا تقبل إضافة/حذف/تعديل يدوي.
- **جدول الرش والطلاء** متاح في مركز البيانات وبطاقة المنتج والطباعة كجدول منفصل (النوع/اللون/المورد/تكلفة القطعة).
- المنتجات غير المرتبطة بمواد رش تُعامل منطقيًا كـ «لا تُرش» وتكون تكلفة الرش لديها 0 (مثال البيانات: 03020024).
- مزامنة جدول الرش مع Supabase تتطلب تطبيق migration `supabase/migrations/20261109_spray_coatings.sql`؛ بدونه يحفظ التطبيق بيانات الرش محليًا ويعمل بشكل طبيعي.

## تطوير المقاسات والألوان (Product Variants)
- لكل منتج `sizes` و`colors` و`variants`؛ التركيبة = (مقاس + لون) ولها مواصفاتها الكاملة: الأبعاد، السعة، الأوزان، CBM، القطع/كرتونة، الباركود، وزن قرص الخام، فرق تكلفة اللون/الخامة، وزمن تشغيل خاص.
- اختيار مقاس أو لون داخل بطاقة المنتج **لا يغيّر المنتج** (`Product ID`/الكود ثابت)؛ يعيد فقط حساب المواصفات والتكلفة والطاقة الإنتاجية للتركيبة المختارة. يتم عرض الألوان المتاحة للمقاس المختار فقط.
- إدارة المقاسات/الألوان/التركيبات من بطاقة المنتج (زر «مقاس»، «لون»، «تركيبة») حسب صلاحية `data.products.edit`.
- تُحفظ التركيبات محليًا (`elzonki.variants.v1`) وتُدمج فوق بيانات الخادم عند كل مزامنة؛ المزامنة بين الأجهزة تحتاج تطبيق migration المقاسات + توسيع `app_factory_bootstrap` لتضمين الأعمدة الجديدة.
- الطباعة تتبع التركيبة المختارة: المقاس واللون والباركود والتكلفة ومواد التعبئة.

## مواد التعبئة والتغليف (Packaging Components)
- سجل كل مادة يحتوي: الاسم، النوع، الكود، الوصف، الخامة، الأبعاد، الوزن، الوحدة، سعر الوحدة، المورد، الحد الأدنى للمخزون، مرحلة الاستخدام (داخلي/خارجي/شحن)، الكمية المستهلكة لكل منتج، وصورة للمادة (عبر مكوّن الصور).
- **الكمية المستهلكة** تُحسب بهذا الترتيب: كمية التركيبة `packagingQty` ← `qtyPerProduct` للسجل ← حصة الكرتونة `1 ÷ pcsPerCarton` للمواد الكرتونية ← 1 لباقي المواد.
- **تكلفة التعبئة للقطعة** = Σ (الكمية المستهلكة × سعر الوحدة)، وتظهر في بطاقة المنتج والطباعة وتدخل في التكلفة تلقائيًا.
- اختلاف مواد التعبئة حسب المقاس/اللون مدعوم عبر `packagingQty` لكل تركيبة.

## معادلات التكلفة المعتمدة
- الخام المباشر = وزن قرص التركيبة × سعر الكيلو.
- الإكسسوارات = Σ (عدد القطع للمنتج × تكلفة الوحدة).
- التعبئة = Σ (الكمية المستهلكة × سعر الوحدة) + الرش/الطلاء + فرق اللون/الخامة.
- المصنعية التقديرية = 11.5% من إجمالي التكلفة المباشرة، والمصاريف غير المباشرة = 12.5% منها (ثوابت `AUTO_LABOR_RATE`/`AUTO_OVERHEAD_RATE` في `src/lib/cost.ts`).
- لا يتم إدخال عناصر التكلفة يدويًا ولا تظهر في مركز البيانات.

## هامش الربح 0% — 200%
- النطاق مقبول كاملًا (0 إلى 200) مع منع القيم السالبة أو الأكبر من 200.
- وضع **هامش من سعر البيع**: السعر = التكلفة ÷ (1 − النسبة) ويُستخدم حتى 99.99%.
- عند 100% أو أكثر (أو عند اختيار **زيادة على التكلفة**): السعر = التكلفة × (1 + النسبة) تلقائيًا، لأن هامش 100% من سعر البيع غير قابل للتمثيل. تعرض البطاقة المعادلة المطبقة والهامش الفعلي بوضوح.
- مثال مفحوص: تكلفة 100 → 0%=100، 50%=200، 100%=200 (هامش فعلي 50%)، 150%=250، 200%=300، ووضع الزيادة 50%=150.

## خطط الإنتاج والتشغيل (Production Planning)
- وحدة مستقلة في القائمة الجانبية (`planning.view`) مع صلاحيات عرض/إنشاء/تعديل/حذف/اعتماد.
- الخطة: كود، اسم، تواريخ، مصنع، خط، وردية، مسؤول، مدة مستهدفة، ملاحظات، ساعات الوردية، عدد الورديات، الآلات المتاحة، التوقف المخطط، ساعات التجهيز.
- البنود: منتج + مقاس/لون (تركيبة) + كمية + ملاحظات، وكل تركيبة بند مستقل.
- تكلفة كل بند من محرك التكلفة الفعلي، والزمن من زمن دورة التركيبة (أو رحلة التصنيع).
- الطاقة: ساعات مطلوبة = Σ(الكمية × زمن القطعة) ÷ 3600 + ساعات التجهيز؛ الطاقة اليومية = ساعات الوردية × الورديات × الآلات × (1 − التوقف)؛ الأيام = تقريب لأعلى؛ تاريخ الانتهاء يتخطى أيام الجمعة؛ نسبة الاستغلال = المطلوب ÷ (الأيام × الطاقة اليومية)، مع تحديد الاختناق.
- حالات الخطة: مسودة، قيد المراجعة، معتمدة، جاهزة للتشغيل، قيد التنفيذ، متوقفة، مكتملة، ملغاة.
- عند الاعتماد تُثبَّت نسخة تكاليف وأسعار وأزمنة (Cost Snapshot) لكل بند، ولا يغيّرها تعديل بطاقة المنتج لاحقًا. الاعتماد يرفض الخطط ذات البيانات الناقصة.
- مقارنة المخطط بالفعلي: الكمية المنتجة، الساعات الفعلية، التكلفة الفعلية، وسبب الانحراف لكل بند.
- التصدير: Excel مباشر، وطباعة/حفظ PDF من نافذة الطباعة.
- تُحفظ الخطط محليًا وتُحاول مزامنتها عبر `app_upsert_production_plan` بعد تطبيق migration.

## صلاحيات مدير الإنتاج
- أضيفت مجموعة «خطط الإنتاج والتشغيل» ومجموعة صلاحيات الإنتاج (`production.edit_times`، `production.edit_capacity`).
- دور «مدير الإنتاج» أصبح يملك إنشاء/تعديل/حذف المنتجات، والمقاسات والألوان، والخامات، والإكسسوارات، ومواد التعبئة، والرش، والخطط، مع بقاء التكاليف الحساسة محجوبة حسب `passport.cost_view`.
- كل صلاحية قابلة للتفعيل/التعطيل من شاشة «الأدوار والصلاحيات»، وكل عملية إضافة/تعديل/حذف/اعتماد تُسجَّل في سجل العمليات باسم المستخدم ووقت العملية.
- حماية البيانات: يُمنع حذف منتج مرتبط بخطط إنتاج (البيانات التاريخية محفوظة) بدل الحذف النهائي.

## تطبيق قاعدة البيانات
- migration جديدة: `supabase/migrations/20261115_variants_packaging_plans.sql` (أعمدة المنتجات، حقول التعبئة، إعدادات التسعير 0–200، جدول `production_plans`، ودوال `app_update_product_variants` و`app_upsert_production_plan` و`app_delete_production_plan` و`app_update_pricing_mode`).
