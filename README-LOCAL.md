# مصانع الزنوكي — تشغيل النسخة المحلية

هذه نسخة كاملة من كود التطبيق تعمل على جهازك عبر `localhost`.

## المتطلبات

- **Node.js 18 أو أحدث** (يُنصح بـ Node.js 20 LTS) — حمّله من https://nodejs.org
- اتصال بالإنترنت، لأن التطبيق يقرأ ويكتب البيانات في قاعدة Supabase السحابية.

للتأكد من التثبيت، افتح Terminal (macOS/Linux) أو Command Prompt (Windows) واكتب:

```bash
node --version
npm --version
```

## خطوات التشغيل

1. فك ضغط الملف `elzonki-local.zip` في أي مجلد على جهازك.
2. افتح Terminal أو Command Prompt **داخل مجلد المشروع** (المجلد الذي يحتوي `package.json`).
3. ثبّت الحزم:

```bash
npm install
```

4. شغّل التطبيق:

```bash
npm run dev
```

5. افتح المتصفح على:

```
http://localhost:5173
```

6. سجّل الدخول بالحساب التجريبي:
   - اسم المستخدم: `admin`
   - كلمة المرور: `admin123`

لإيقاف الخادم اضغط `Ctrl + C` في الـ Terminal.

## أوامر إضافية

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل خادم التطوير على المنفذ 5173 |
| `npm run build` | إنشاء نسخة إنتاج في مجلد `dist` |
| `npm run preview` | معاينة نسخة الإنتاج محليًا |
| `npm run typecheck` | فحص أنواع TypeScript |

إذا كان المنفذ 5173 مشغولًا، شغّل على منفذ آخر:

```bash
npm run dev -- --port 5174
```

## إعدادات قاعدة البيانات

ملف `.env.local` مضمّن ويحتوي مفتاحي الاتصال بمشروع Supabase الحالي:

```env
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

هذا يعني أن النسخة المحلية **تتشارك نفس البيانات** مع النسخة المنشورة على الإنترنت: أي تعديل تجريه محليًا سيظهر هناك، والعكس صحيح. إذا أردت قاعدة مستقلة، أنشئ مشروع Supabase جديدًا، وطبّق ملفات `supabase/migrations` بالترتيب، ثم ضع بيانات المشروع الجديد في `.env.local`.

لسرية أعلى: لا تشارك مجلد المشروع مع أي شخص آخر طالما أن `.env.local` بداخله.

## حل المشكلات

- **`npm` غير معروف**: أعد تثبيت Node.js وتأكد من إغلاق وفتح Terminal بعد التثبيت.
- **فشل الاتصال بالبيانات**: تأكد من وجود `.env.local` في جذر المشروع ومن صحة قيم المفاتيح.
- **صفحة بيضاء**: افتح Console في المتصفح واطلع على الخطأ، وتأكد أنك تشغّل الأمر من مجلد المشروع الصحيح.
